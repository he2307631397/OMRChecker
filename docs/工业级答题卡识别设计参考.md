# 工业级答题卡识别设计参考

本文整理答题卡识别（OMR, Optical Mark Recognition）的工业级技术方案、典型开源选型与落地建议。目标是在标准扫描、高拍仪、手机拍照等输入条件下，提高对淡涂、半涂、擦除残留、误涂等真实填涂场景的识别稳定性。

## 1. 背景与目标

传统纯 OpenCV 方案在标准扫描件上表现稳定，但在手机拍照、光照不均、纸张倾斜、局部阴影和填涂不规范场景下容易出现误判或漏判。工业级系统通常不应只依赖固定阈值，而应结合图像定位、几何校正、局部对比度、连通域分析、置信度评估以及必要的轻量级模型分类。

本文建议的总体目标如下：

- 在清晰扫描件或高拍仪图像中保持接近 100% 的稳定识别率。
- 在手机拍照、弱填涂、擦除残留等复杂场景下提升鲁棒性。
- 保持主识别链路高性能，避免为少量异常样本牺牲整体吞吐。
- 对低置信度结果提供可解释诊断和人工复核入口。

## 2. 推荐总体架构：传统 CV + 置信度判定 + 轻量模型

为了兼顾处理速度和极限准确率，推荐采用双阶段过滤架构。传统 CV 负责定位、校正、切片和大部分明显填涂判断，轻量级模型只处理置信度灰区样本。

```text
[输入答题卡图像]
        │
        ▼
[图像预处理]
灰度化 / 去噪 / 自适应二值化 / 光照校正
        │
        ▼
[定位与几何校正]
定位点检测 / 轮廓提取 / 透视变换 / 版面归一化
        │
        ▼
[选项 ROI 切片]
按模板切出每个选项格子
        │
        ▼
[阶段一：快速硬过滤]
明显填涂、明显空白直接判定
        │
        ├── 高置信度结果 ──> 输出识别结果
        │
        ▼
[阶段二：置信度灰区处理]
淡涂 / 半涂 / 擦除残留 / 误涂冲突
        │
        ▼
[轻量级 CNN 或综合规则分类]
输出最终填涂概率和诊断信息
```

该架构的核心思路是：多数正常样本由传统 CV 快速完成，只有少量模糊样本进入更复杂的判定链路。这样既能保持速度，又能提高对真实异常填涂行为的容错能力。

## 3. 核心处理流程

### 3.1 图像定位与几何校正

答题卡应尽量设计稳定的定位锚点，例如四角黑色定位块、边缘定位线、二维码或条形码。识别时通过 Canny 边缘检测、轮廓提取、角点检测等方式锁定卡面位置，再使用透视变换将图像拉正。

关键能力包括：

- 自动纠正倾斜、旋转和拍照透视变形。
- 抑制折痕、阴影和背景噪声对定位点的影响。
- 将答题卡统一映射到模板坐标系，保证 ROI 切片稳定。

### 3.2 图像预处理

预处理阶段不建议只使用固定阈值。更稳健的方式是结合页面级和局部区域级统计信息。

推荐处理步骤：

1. 转灰度并做轻量去噪。
2. 对光照不均区域进行背景估计或亮度平滑。
3. 使用自适应阈值或局部对比度方法处理弱填涂。
4. 对选项格子进行形态学处理，减少孤立噪声点影响。
5. 保留原始灰度图特征，供后续相对灰度和置信度计算使用。

### 3.3 ROI 切片与特征提取

每个选项格子应被切成固定大小的 ROI，例如 `48 x 48` 或 `64 x 64`。对每个 ROI 计算以下特征：

- 平均灰度值 `mean`。
- 黑色像素比例 `darkRatio`。
- 中心区域墨迹密度 `centerDensity`。
- 边缘区域墨迹密度 `edgeDensity`。
- 连通域数量、面积和连通覆盖率 `connectedRatio`。
- 填涂区域覆盖率。
- 选项内墨迹分布的集中度与离散度。
- 与同题其他选项的相对黑度差。
- 与本页空白基线的相对灰度差。

这些特征可组织为统一的 `BubbleFeature`，用于传统规则判定、轻量模型输入和诊断日志。

```text
BubbleFeature
- mean
- darkRatio
- centerDensity
- edgeDensity
- connectedRatio
```

## 4. 极端填涂场景与算法策略

### 4.1 淡涂

**典型表现：** 使用 HB 铅笔、浅色圆珠笔或填涂力度较轻，导致选项区域绝对灰度值接近白纸背景。

**风险：** 固定阈值容易把淡涂识别为空白。

**建议策略：** 使用局部相对对比度法，而不是只看全局黑度。

- 计算当前 ROI 与周边空白区域的灰度差。
- 使用页面空白基线和同题空白候选作为参考。
- 只要当前格子相对背景明显变暗，即使绝对黑度不高，也可进入候选填涂集合。
- 对弱填候选输出置信度，而不是直接强判。

### 4.2 半涂、缺涂或勾画

**典型表现：** 学生只画勾、点点、画圈或只涂满一半区域。

**风险：** 单纯依赖填涂面积比例会漏判。

**建议策略：** 结合连通域重心、动态密度和形状特征。

- 不把填涂面积作为唯一指标。
- 统计黑色像素的空间分布和连通域覆盖范围。
- 对勾画、圈画等非标准形状引入轻量分类模型。
- 对单选题结合题内排序判断最可能选项。

### 4.3 擦除未净

**典型表现：** 学生先涂 A 后改涂 B，A 中留下石墨残影、阴影或纸面凹痕。

**风险：** 残留痕迹可能被误判为多选。

**建议策略：** 使用单题内部最大值比对、中心/边缘密度和纹理判断。

- 在同一道题内部比较各选项的相对黑度。
- 计算 `当前选项得分 / 本题最高得分`。
- 分别统计中心区域和边缘区域的墨迹密度。完整填涂通常中心墨迹连续，擦除残留通常中心较干净、边缘或局部仍有残影。
- 可使用 `FillScore = centerDensity - edgeDensity` 判断是否更像有效填涂。
- 可使用 `EraseScore = edgeDensity - centerDensity + residualArea` 判断是否更像擦除痕迹。
- 若某选项明显低于最高得分，且纹理斑驳不均，可标记为 `ERASE_TRACE`。
- 对多选题要结合模板配置，避免把合法多选误过滤。

### 4.4 误涂、多涂和冲突选择

**典型表现：** 单选题出现多个疑似填涂项，或者不同选项得分非常接近。

**风险：** 直接按最黑选项输出可能掩盖真实冲突，影响评分公平性。

**建议策略：** 引入题型约束、选项状态分类和人工复核机制。

建议将每个选项归类为以下状态：

```text
EMPTY       空白
MARK        明确填涂
WEAK_MARK   弱填涂候选
ERASE_TRACE 擦除残留
```

判定规则：

- 单选题中若只有一个 `MARK`，其余为 `EMPTY` 或低置信度 `ERASE_TRACE`，可输出该选项并记录擦除痕迹。
- 单选题中若多个选项为 `MARK` 或多个 `WEAK_MARK` 置信度接近，应标记为 `ambiguous_single_choice`。
- 多选题中按模板允许的多选规则输出结果。
- 对置信度处于灰区的题目高亮显示，交由人工确认。
- 记录每个选项的状态、得分、相对排名和判定原因，便于追溯。

## 5. 开源技术栈选型

### 5.1 OMRChecker

**技术栈：** Python + OpenCV

**适用场景：** 标准扫描件、高拍仪、可控模板、需要快速二次开发的 OMR 任务。

**优势：**

- 具备完整 OMR 处理流程。
- 支持倾斜校正和可视化调试。
- 支持自定义评分机制，例如小题计分、多选题、倒扣分等。
- 适合作为本项目继续优化弱填涂和擦除识别的基础。

**建议改造方向：**

- 将固定 `pixel_density` 判定升级为相对密度和局部对比度判定。
- 在题目解析循环中加入同题横向比对逻辑。
- 对低置信度候选输出诊断信息。
- 保持主识别链路稳定，把弱填恢复作为 fallback。

### 5.2 FormReturn

**技术栈：** Java / 多平台

**适用场景：** 需要完整企业级闭环，包括答题卡设计、打印、采集、识别和数据管理。

**优势：**

- 自带版式设计器。
- 支持通过条形码或二维码关联学生信息和定位信息。
- 工业规范度高，适合参考系统设计和卡面规范。

### 5.3 answer-sheet-scan

**技术栈：** Python + OpenCV

**适用场景：** 需要学习或快速实现透视校正、自适应二值化、亮度平滑和连通域提取的场景。

**优势：**

- 对传统 OpenCV 流程讲解清晰。
- 适合作为定位、纠偏和切片逻辑的参考。
- 对摄像头拍摄畸变问题有一定参考价值。

### 5.4 PaddleClas / MobileNet / ShuffleNet

**技术栈：** PaddlePaddle 或 PyTorch

**适用场景：** 手机拍照、填涂不规范、淡涂和擦除残留较多的复杂业务场景。

**建议方案：**

- 使用 OpenCV 完成定位和 ROI 切片。
- 收集标准涂、淡涂、打勾、擦除残留、空白等样本。
- 将 ROI 训练为 `Filled` / `Empty` 二分类，或扩展为多类别诊断模型。
- 使用 MobileNetV3-Small、ShuffleNetV2 等轻量网络部署到 CPU 推理。

## 6. 推荐落地方案

### 6.1 轻量高效方案：纯 OpenCV 深度优化

适合资源受限、输入相对稳定、需要快速落地的场景。

实施重点：

1. 保持主识别流程不变。
2. 增加页面级空白基线估计。
3. 增加 `BubbleFeature`，至少包含 `mean`、`darkRatio`、`centerDensity`、`edgeDensity`。
4. 增加题内横向相对黑度比对。
5. 对正常识别为空白的字段启动弱填 fallback。
6. 增加选项状态分类，包括 `EMPTY`、`MARK`、`WEAK_MARK`、`ERASE_TRACE`。
7. 对冲突和低置信度结果输出人工复核标记。

### 6.2 商业级方案：OpenCV 定位 + 轻量模型分类

适合手机拍照、复杂光照、填涂习惯不稳定的场景。

实施重点：

1. 通过 OpenCV 完成稳定定位、透视校正和 ROI 切片。
2. 将模糊样本送入轻量级 CNN 分类器。
3. 将模型输出与传统特征融合为最终置信度。
4. 对低置信度题目进入人工复核流程。
5. 持续积累人工复核样本，用于后续模型迭代。

## 7. 工业级实施建议

### 7.1 卡面设计

卡面设计应尽量降低后续识别难度。

- 在答题卡四角放置稳定定位点。
- 为选项区域预留足够边距，避免印刷线干扰 ROI。
- 可使用红色或浅色辅助框，在识别时通过色彩分离降低干扰。
- 使用二维码或条形码绑定模板、学生信息和批次信息。

### 7.2 识别诊断与可视化

工业系统不应只输出最终答案，还应输出判定过程。

建议记录：

- 每个 ROI 的灰度、密度、连通域和置信度。
- 每道题的选项排序和冲突状态。
- 进入 fallback 的字段及原因。
- 低置信度样本的裁剪图，供人工复核和模型训练。

### 7.3 人工复核机制

对于教学考试等严肃场景，低置信度结果应进入人工复核。

推荐规则：

- 置信度明显高于阈值：自动判定。
- 置信度明显低于阈值：自动判为空白。
- 置信度处于灰区：高亮展示并人工确认。
- 单选题多项接近：标记冲突，不直接猜测。

## 8. 实施路线建议

建议按以下顺序推进，避免一次性引入过多复杂度：

1. **第一阶段：文档化现有识别链路**  
   明确当前模板、ROI、阈值、评分和输出流程。

2. **第二阶段：增加相对灰度与弱填 fallback**  
   优先解决淡涂、轻涂和整体偏亮样本。

3. **第三阶段：增加 BubbleFeature 与选项状态分类**  
   引入 `mean`、`darkRatio`、`centerDensity`、`edgeDensity`，并输出 `EMPTY`、`MARK`、`WEAK_MARK`、`ERASE_TRACE`。

4. **第四阶段：增加擦除和冲突处理**  
   引入中心/边缘密度比对、擦除痕迹评分、同题横向比对、单选冲突标记和人工复核。

5. **第五阶段：积累模糊样本数据集**  
   保存低置信度 ROI、弱填 ROI、擦除残留 ROI 和人工复核结果，用于后续模型训练。

6. **第六阶段：引入轻量级模型**  
   仅对灰区样本推理，模型输出 `mark_probability` 和 `erase_probability`，保持主链路性能稳定。

## 9. 总结

工业级答题卡识别不应依赖单一阈值。更稳健的方案是以 OpenCV 完成稳定定位和高性能基础识别，再通过相对灰度、题内比对、置信度模型和人工复核机制处理复杂填涂场景。

对于当前 OMRChecker 项目，推荐优先采用“主识别链路不变 + 弱填 fallback + 擦除痕迹检测 + 诊断日志 + 冲突复核”的渐进式路线。该路线风险低、可验证性强，也为后续引入轻量级模型留下了清晰接口。
