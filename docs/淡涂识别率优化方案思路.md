# 淡涂识别率优化方案思路

## 背景

当前淡涂场景的剩余空白不是完全没有图像信号，而是信号强度介于“明确填涂”和“空白/噪声”之间：

- 页面级证据较强，淡涂候选通常比整页空白泡更深。
- 题内局部证据不足，候选和同题其它选项的灰度差距不总是足够大。
- 现有 fallback 主要被 `adaptive_min_delta_from_blank` 拒绝。
- 简单降低全局阈值或局部阈值会扩大误识别风险，可能影响正常填涂、涂超出、没涂满、多选和学号识别。

因此，优化方向不应是放松主阈值，而应是在主识别结果为空白时，增加一个受保护的弱填候选审查层。

## 目标

在不做样本特化的前提下，提高淡涂识别率，并保持已有识别成果不退化。

必须满足：

- 不硬编码文件名、目录、样本编号、题号、坐标、答案或例外。
- 不简单降低全局阈值。
- 不覆盖主识别流程已经识别出的结果。
- 不破坏正常填涂 56 张无空白的回归门禁。
- 不让涂超出场景新增误识别或异常。
- 不把没涂满场景中本应空白的 ID 行强行恢复。
- 不破坏已有多选、弱填、学号 fallback 的安全边界。

## 核心判断

淡涂识别不能只看一个灰度阈值。工业级答题卡识别通常会组合页面级、题内级和 ROI 级证据，区分以下几类情况：

1. **真实淡涂**：候选整体较浅，但中心区域存在连续暗像素，且相对页面空白明显更深。
2. **空白波动**：所有选项都接近空白，最深候选只是随机噪声。
3. **边框或污染**：边缘暗、中心不暗，容易被普通均值误判。
4. **涂超出**：暗像素可能扩散到边缘或多个候选，单选恢复需要谨慎。
5. **没涂满/擦痕**：局部有痕迹但结构不稳定，应优先进入 REVIEW，而不是自动恢复。

## 推荐方案：证据分层 + 保守恢复

### 1. 主识别流程保持不变

现有阈值流程仍然是第一判断源。只有当某个单选字段主流程输出为空白时，才进入弱填审查。

这能保证：

- 正常深涂仍由主流程处理。
- 已识别答案不会被 fallback 改写。
- fallback 的影响范围可控。

### 2. 候选生成

对一个空白单选题，只选同题内均值最深的一个泡作为候选。

前置条件：

- 字段类型是支持的单选类型，例如 `QTYPE_MCQ4`。
- 字段不是 `multi_select`。
- 当前字段主流程没有识别出答案。
- 当前字段没有被弱多选 fallback 或全选 fallback 处理。
- 字段 label 不在排除列表中。

不对 ID 行使用此单选逻辑。ID 行继续走已有 `weak_identifier_params` 逻辑。

### 3. 通用 BubbleFeature

对每个候选泡提取通用特征，而不是针对样本调参。

建议特征：

| 特征 | 含义 | 用途 |
| --- | --- | --- |
| `mean` | 泡整体灰度均值 | 基础深浅指标 |
| `delta_from_page_blank` | 页面空白基线与候选均值差 | 判断候选是否比整页空白明显更深 |
| `page_z_score` | 候选相对页面空白分布的 z-score | 抗扫描亮度差异 |
| `delta_from_field_blank` | 本题空白基线与候选均值差 | 判断题内相对深度 |
| `gap_to_second` | 最深候选与第二深候选的差 | 判断单选唯一性 |
| `inner_dark_ratio` | 内部 ROI 暗像素比例 | 捕捉淡涂核心痕迹 |
| `center_density` | 中心区域暗像素密度 | 区分真实填涂和边缘噪声 |
| `edge_density` | 边缘区域暗像素密度 | 发现边框、污染、涂超出风险 |
| `center_edge_ratio` | 中心密度与边缘密度比值 | 中心填涂应强于边缘污染 |
| `density_gap` | 最深候选暗像素密度与第二候选差 | 进一步判断唯一性 |

这些特征都来自页面、字段和泡 ROI 本身，不依赖文件名、题号或坐标例外。

### 4. 页面空白基线

页面空白基线建议继续使用稳健估计：

- 收集全页所有泡的均值。
- 取较亮的一段作为空白样本。
- 计算 `blank_mean` 和 `blank_std`。
- 用 `delta_from_page_blank` 与 `page_z_score` 判断候选是否显著偏深。

这样可以适配不同扫描亮度、纸张底色和整体曝光差异。

### 5. 题内相对基线

单个题目内，还需要比较候选和其它选项：

- 最深候选不能只比其它候选深一点点。
- 如果第二候选也很深，说明可能有污染、涂超出、多选或模糊状态。
- 题内证据不足时，即使页面证据较强，也不应直接恢复。

这就是为什么不能简单绕过 `adaptive_min_delta_from_blank`。更合理的做法是：允许页面证据和 ROI 密度补充题内证据，但不能完全无条件替代它。

## 判定策略

建议采用三态输出：

1. `WEAK_MARK`：证据强，自动恢复答案。
2. `REVIEW`：有弱填迹象，但存在歧义，不自动恢复，只写日志。
3. `EMPTY`：证据不足，保持空白。

### 自动恢复条件

自动恢复应满足“硬门槛 + 多证据评分”。

硬门槛建议包括：

- 候选均值不能超过安全上限，例如过亮时不恢复。
- 候选必须相对页面空白有足够深度差。
- 候选不能和第二候选高度接近。
- 中心密度不能明显低于边缘密度。
- 边缘污染或多候选接近时，不自动恢复。

评分证据可包括：

- 页面级深度差达到要求。
- 页面 z-score 达到要求。
- 中心 ROI 有足够暗像素。
- 内部暗像素比例达到要求。
- 与第二候选有一定 gap。
- 与本题空白基线有一定 delta。
- 密度 gap 支持唯一候选。

只有总分达到高置信阈值，才输出 `WEAK_MARK`。

### REVIEW 条件

以下情况应进入 `REVIEW`，而不是自动恢复：

- 页面证据强，但题内 gap 很小。
- 中心密度存在，但边缘密度同样高。
- 候选和第二候选都偏深。
- 只有均值变深，但 ROI 暗像素结构不明显。
- 疑似擦痕、半涂、污染、涂超出。

`REVIEW` 的价值是帮助后续分析，但不改变识别结果。

## 与现有 fallback 的关系

建议处理顺序保持保守：

1. 主阈值识别。
2. 单选冲突处理。
3. 弱多选 fallback。
4. 弱多选全选 fallback。
5. 单选弱填 feature fallback。
6. 学号弱填 fallback。

单选弱填 fallback 只在前面都没有产出结果时触发。这样不会覆盖多选、全选或学号逻辑。

## 为什么先日志观测，再启用恢复

当前已经知道淡涂失败项主要卡在局部分离度不足。但在启用自动恢复前，仍应先用四类场景跑一轮特征观测：

- 淡涂剩余空白是否具备稳定的页面证据和中心密度。
- 正常场景是否会出现大量 REVIEW 或潜在误恢复候选。
- 涂超出场景是否表现为边缘密度高或多候选接近。
- 没涂满场景是否表现为低中心密度、低唯一性或高歧义。

如果日志显示真实淡涂和风险样本的特征可分，再启用自动恢复。否则应只保留 REVIEW 日志，不自动填答案。

## 回归门禁

每次代码或参数变更后，都应运行同一套四场景统计：

| 场景 | 门禁 |
| --- | --- |
| 正常填涂 | 56 行，ID 和题目空白数为 0 |
| 淡涂 | 空白数应小于当前基线 4，或剩余空白有 REVIEW 解释 |
| 没涂满 | 不能把本应空白的 ID 行强行恢复 |
| 涂超出 | 4 行，不能新增空白、异常或明显误恢复 |

同时统计日志：

- `Weak mark fallback`
- `Weak mark candidate review`
- `Weak identifier fallback`
- `Weak multi-mark fallback`
- `Single-choice conflict`

## 具体实施建议

### 第一阶段：观测模式

- 添加 `BubbleFeature` 提取。
- 对主流程为空白的单选题计算 feature。
- 不自动恢复，只输出 REVIEW/EMPTY 日志。
- 跑四场景，保存每类场景的候选特征分布。

### 第二阶段：保守恢复

- 基于通用特征设置高置信恢复规则。
- 只恢复 `WEAK_MARK`，不恢复 `REVIEW`。
- 保持默认配置可关闭，避免影响其它用户。
- 对当前 inputs 可以显式开启，用于回归验证。

### 第三阶段：回归固化

- 建立可重复运行脚本。
- 输出 rows、blank cells、fallback/review 计数。
- 将正常、没涂满、涂超出作为硬门禁。
- 只有四场景全部通过，才保留自动恢复。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 把空白噪声恢复成答案 | 页面证据、中心密度、gap 多条件同时满足 |
| 把涂超出误判成单选 | 用边缘密度、多候选接近、density gap 做歧义拦截 |
| 把没涂满 ID 强行恢复 | 单选 fallback 不作用于 ID，ID 继续走独立逻辑 |
| 影响正常填涂 | fallback 只处理主流程空白字段 |
| 参数针对样本过拟合 | 参数仅表达通用特征阈值，必须通过四场景回归 |
| 弱填和多选逻辑冲突 | 多选和已有弱多选 fallback 优先，单选 fallback 最后触发 |

## 推荐结论

推荐采用“先观测、再恢复”的方案，而不是直接放宽现有阈值。

最安全的落地路径是：

1. 先实现通用 BubbleFeature 和 REVIEW 日志。
2. 跑四场景，确认淡涂、正常、没涂满、涂超出的特征差异。
3. 再启用高置信 `WEAK_MARK` 自动恢复。
4. 如果三类保护场景出现风险，立即退回 REVIEW-only，不自动改答案。

这个方案符合工业级答题卡识别思路：用多层证据、局部 ROI 特征、页面空白基线和风险分级来处理淡涂，而不是针对某批样本硬调阈值。
