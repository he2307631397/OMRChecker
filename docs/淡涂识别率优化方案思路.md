# OMRChecker 淡涂识别率优化方案：动态阈值、多尺度 ROI 与保守 Fallback

## 背景

当前项目是 OMRChecker，识别链路以模板定位、泡 ROI、灰度均值、阈值和 fallback 规则为主。
因此，淡涂优化应优先采用 OpenCV 和统计特征方案，而不是直接引入深度学习。

当前淡涂场景的剩余空白不是完全没有图像信号，而是信号强度介于“明确填涂”和“空白/噪声”之间：

- 页面级证据较强，淡涂候选通常比整页空白泡更深。
- 题内局部证据不足，候选和同题其它选项的灰度差距不总是足够大。
- 现有 fallback 容易被 `adaptive_min_delta_from_blank`、gap 或密度条件拒绝。
- 简单降低全局阈值会扩大误识别风险，可能影响正常填涂、涂超出、没涂满、多选和学号识别。

因此，优化方向不是放松主识别阈值，而是在主识别结果为空白时，增加一个受保护的弱填候选审查层。
该审查层使用页面空白基线、题内相对对比、ROI 结构、多尺度 ROI 和动态多阈值投票形成证据。

## 目标

在不做样本特化的前提下，提高淡涂识别率，并保持已有识别成果不退化。

必须满足：

- 不硬编码文件名、目录、样本编号、题号、坐标、答案或例外。
- 不简单降低全局阈值。
- 不覆盖主识别流程已经识别出的结果。
- 不破坏正常填涂 56 张无空白的回归门禁。
- 不让涂超出场景新增误识别或异常。
- 不把没涂满场景中本应空白的 ID 行强行恢复。
- 不破坏已有多选、弱填、学号 fallback 的安全边界。
- 当前阶段不引入 CNN 或训练模型，深度学习只作为远期灰区辅助方向。

## 当前阶段不采用 CNN

工业级答题卡识别可以在灰区引入 PaddleClas、MobileNetV3、ShuffleNetV2 等轻量 CNN。
但对当前 OMRChecker 项目，CNN 不适合作为本阶段主线：

- 需要持续积累低置信 ROI、弱填 ROI、擦除残留 ROI 和人工复核标签。
- 需要训练、验证、部署和模型版本管理。
- 需要证明不会破坏已有正常填涂、涂超出、没涂满和多选识别成果。
- 当前问题仍可先通过 OpenCV 统计特征、动态阈值和多尺度 ROI 获得可解释改进。

因此，当前方案限定为：主流程不变，fallback 只处理空白单选字段，用可解释特征输出 `WEAK_MARK`、`REVIEW` 或 `EMPTY`。

## 核心判断

淡涂识别不能只看一个灰度阈值。OMRChecker 的可落地方案应组合页面级、题内级、ROI 级和多尺度稳定性证据，区分以下情况：

1. **真实淡涂**：候选整体较浅，但中心区域存在连续暗像素，且相对页面空白明显更深。
2. **空白波动**：所有选项都接近空白，最深候选只是随机噪声。
3. **边框或污染**：边缘暗、中心不暗，容易被普通均值误判。
4. **涂超出**：暗像素可能扩散到边缘或多个候选，单选恢复需要谨慎。
5. **没涂满/擦痕**：局部有痕迹但结构不稳定，应优先进入 `REVIEW`，而不是自动恢复。

## 推荐方案：证据分层 + 动态阈值 + 多尺度 ROI + 保守恢复

### 1. 主识别流程保持不变

现有阈值流程仍然是第一判断源。只有当某个单选字段主流程输出为空白时，才进入弱填审查。

这能保证：

- 正常深涂仍由主流程处理。
- 已识别答案不会被 fallback 改写。
- fallback 的影响范围可控。
- 原有 OMRChecker 模板、阈值和导出行为不被大范围扰动。

### 2. 候选生成

对一个空白单选题，只选同题内均值最深的一个泡作为候选。

前置条件：

- 字段类型是支持的单选类型，例如 `QTYPE_MCQ4`。
- 字段不是 `multi_select`。
- 当前字段主流程没有识别出答案。
- 当前字段没有被弱多选 fallback 或全选 fallback 处理。
- 字段 label 不在排除列表中。

不对 ID 行使用此单选逻辑。ID 行继续走已有 `weak_identifier_params` 逻辑。

### 3. 通用 BubbleFeature

对每个候选泡提取通用特征，而不是针对样本调参。

建议特征：

| 特征 | 含义 | 用途 |
| --- | --- | --- |
| `mean` | 泡整体灰度均值 | 基础深浅指标 |
| `delta_from_page_blank` | 页面空白基线与候选均值差 | 判断候选是否比整页空白明显更深 |
| `page_z_score` | 候选相对页面空白分布的 z-score | 抗扫描亮度差异 |
| `delta_from_field_blank` | 本题空白基线与候选均值差 | 判断题内相对深度 |
| `gap_to_second` | 最深候选与第二深候选的差 | 判断单选唯一性 |
| `inner_dark_ratio` | 内部 ROI 暗像素比例 | 捕捉淡涂核心痕迹 |
| `center_density` | 中心区域暗像素密度 | 区分真实填涂和边缘噪声 |
| `edge_density` | 边缘区域暗像素密度 | 发现边框、污染、涂超出风险 |
| `center_edge_ratio` | 中心密度与边缘密度比值 | 判断中心填涂是否强于边缘污染 |
| `density_gap` | 最深候选暗像素密度与第二候选差 | 进一步判断唯一性 |
| `threshold_vote_count` | 动态多阈值下的命中次数 | 判断弱填是否跨阈值稳定 |
| `scale_stability` | 多尺度 ROI 下的候选稳定性 | 判断淡涂信号是否稳定存在 |

这些特征都来自页面、字段和泡 ROI 本身，不依赖文件名、题号、坐标或答案例外。

## 动态阈值策略

### 1. 页面级动态阈值

页面空白基线建议继续使用稳健估计：

- 收集全页所有泡的均值。
- 取较亮的一段作为空白样本。
- 计算 `page_blank_mean` 和 `page_blank_std`。
- 用 `delta_from_page_blank` 与 `page_z_score` 判断候选是否显著偏深。

示意：

```text
page_delta = page_blank_mean - candidate_mean
page_z = page_delta / max(page_blank_std, 1)
```

这样可以适配不同扫描亮度、纸张底色和整体曝光差异。

### 2. 题内动态阈值

单个题目内，还需要比较候选和其它选项：

```text
local_delta = local_blank_mean - darkest_mean
gap = second_darkest_mean - darkest_mean
```

判断原则：

- 最深候选不能只比其它候选深一点点。
- 如果第二候选也很深，说明可能有污染、涂超出、多选或模糊状态。
- 题内证据不足时，即使页面证据较强，也不应直接自动恢复。

这就是为什么不能简单绕过 `adaptive_min_delta_from_blank`。
更合理的做法是允许页面证据、ROI 密度和多阈值稳定性补充题内证据，但不能无条件替代题内唯一性。

### 3. ROI 多阈值投票

不建议使用固定全局阈值，例如“灰度小于某个常数就是填涂”。
应围绕页面或题内空白基线生成多档动态阈值：

```text
thresholds = [blank_mean - 10, blank_mean - 15, blank_mean - 20, blank_mean - 25]
```

其中 `10/15/20/25` 不是样本特化参数，而是相对空白基线的通用观察档位。
这些档位只产生证据，不直接决定答案。

对每个阈值计算：

- 候选中心 ROI 的暗像素比例。
- 候选整体 ROI 的暗像素比例。
- 候选与第二候选的暗像素比例差。
- 候选是否在多档阈值下都保持题内第一。

如果候选只在最宽松阈值下偶然命中，倾向 `REVIEW` 或 `EMPTY`。
如果候选在多档动态阈值下稳定领先，才能增加 `WEAK_MARK` 证据。

## 多尺度 ROI / 小型图像金字塔

图像金字塔不需要深度学习，可以作为 OpenCV 特征增强方式。
对当前 OMRChecker，建议只在 blank-only fallback 中使用小型多尺度 ROI，不替代主识别流程。

### 建议的多尺度观察

对同一个泡 ROI 生成少量派生视图：

1. **原始 ROI**：保持现有 OMRChecker 行为，用于兼容已有统计。
2. **中心收缩 ROI**：去掉边框和外圈，突出真实填涂中心。
3. **轻微模糊 ROI**：降低扫描噪声对暗像素比例的影响。
4. **轻微缩放 ROI**：模拟小型图像金字塔，观察弱填信号是否跨尺度稳定。

每个尺度都计算 `dark_ratio`、`center_density`、`edge_density` 和题内排名。
最终形成：

```text
scale_stability = 多尺度下候选保持最深或中心密度领先的比例
```

### 使用边界

多尺度 ROI 只能增强证据，不能单独触发自动恢复。
它必须和页面级动态阈值、题内 gap、中心/边缘密度一起判断。

风险控制：

- 边缘密度高但中心不强，倾向污染或涂超出。
- 多个候选在多尺度下都偏深，倾向多选、涂超出或冲突。
- 只有模糊后才明显变暗，原始和中心 ROI 不支持时，不自动恢复。

## 判定策略

建议采用三态输出：

1. `WEAK_MARK`：证据强，自动恢复答案。
2. `REVIEW`：有弱填迹象，但存在歧义，不自动恢复，只写日志。
3. `EMPTY`：证据不足，保持空白。

### 自动恢复条件

自动恢复应满足“硬门槛 + 多证据评分”。

硬门槛建议包括：

- 候选均值不能超过安全上限，例如过亮时不恢复。
- 候选必须相对页面空白有足够深度差。
- 候选不能和第二候选高度接近。
- 中心密度不能明显低于边缘密度。
- 边缘污染或多候选接近时，不自动恢复。
- 多阈值投票不能只在最宽松档位命中。
- 多尺度 ROI 不能显示多个候选同时偏深。

评分证据可包括：

- 页面级深度差达到要求。
- 页面 z-score 达到要求。
- 中心 ROI 有足够暗像素。
- 内部暗像素比例达到要求。
- 与第二候选有一定 gap。
- 与本题空白基线有一定 delta。
- 密度 gap 支持唯一候选。
- 动态多阈值投票稳定命中。
- 多尺度 ROI 下候选保持领先。

只有总分达到高置信阈值，才输出 `WEAK_MARK`。

### REVIEW 条件

以下情况应进入 `REVIEW`，而不是自动恢复：

- 页面证据强，但题内 gap 很小。
- 中心密度存在，但边缘密度同样高。
- 候选和第二候选都偏深。
- 只有均值变深，但 ROI 暗像素结构不明显。
- 只有最宽松动态阈值命中。
- 只有模糊或缩放后出现信号，原始 ROI 不支持。
- 疑似擦痕、半涂、污染、涂超出。

`REVIEW` 的价值是帮助后续分析，但不改变识别结果。

## 与现有 fallback 的关系

建议处理顺序保持保守：

1. 主阈值识别。
2. 单选冲突处理。
3. 弱多选 fallback。
4. 弱多选全选 fallback。
5. 单选弱填 feature fallback。
6. 学号弱填 fallback。

单选弱填 fallback 只在前面都没有产出结果时触发。
这样不会覆盖多选、全选或学号逻辑。

## 为什么先日志观测，再启用恢复

当前已经知道淡涂失败项主要卡在局部分离度不足。
但在启用自动恢复前，仍应先用四类场景跑一轮特征观测：

- 淡涂剩余空白是否具备稳定的页面证据、中心密度、多阈值投票和多尺度稳定性。
- 正常场景是否会出现大量 `REVIEW` 或潜在误恢复候选。
- 涂超出场景是否表现为边缘密度高、多候选接近或尺度下扩散。
- 没涂满场景是否表现为低中心密度、低唯一性或高歧义。

如果日志显示真实淡涂和风险样本的特征可分，再启用自动恢复。
否则应只保留 `REVIEW` 日志，不自动填答案。

## 回归门禁

每次代码或参数变更后，都应运行同一套四场景统计：

| 场景 | 门禁 |
| --- | --- |
| 正常填涂 | 56 行，ID 和题目空白数为 0 |
| 淡涂 | 空白数应小于当前基线 4，或剩余空白有 `REVIEW` 解释 |
| 没涂满 | 不能把本应空白的 ID 行强行恢复 |
| 涂超出 | 4 行，不能新增空白、异常或明显误恢复 |

同时统计日志：

- `Weak mark fallback`
- `Weak mark candidate review`
- `Weak identifier fallback`
- `Weak multi-mark fallback`
- `Single-choice conflict`
- `threshold_vote_count`
- `scale_stability`

## 具体实施建议

### 第一阶段：观测模式

- 添加或完善 `BubbleFeature` 提取。
- 对主流程为空白的单选题计算 feature。
- 增加页面级动态阈值、题内动态阈值和 ROI 多阈值投票。
- 增加小型多尺度 ROI 特征，包括中心收缩、轻微模糊和轻微缩放。
- 不自动恢复，只输出 `REVIEW`/`EMPTY` 日志。
- 跑四场景，保存每类场景的候选特征分布。

### 第二阶段：保守恢复

- 基于通用特征设置高置信恢复规则。
- 只恢复 `WEAK_MARK`，不恢复 `REVIEW`。
- 保持默认配置可关闭，避免影响其它用户。
- 对当前 inputs 可以显式开启，用于回归验证。
- 如果保护场景出现风险，立即退回 review-only。

### 第三阶段：回归固化

- 建立可重复运行脚本。
- 输出 rows、blank cells、fallback/review 计数。
- 输出动态阈值投票和多尺度稳定性统计。
- 将正常、没涂满、涂超出作为硬门禁。
- 只有四场景全部通过，才保留自动恢复。

### 远期阶段：轻量模型灰区辅助

如果后续积累了足够的低置信 ROI 和人工复核标签，可以单独评估轻量 CNN。
它只应处理 `REVIEW` 灰区，不应替代 OMRChecker 主识别流程。

远期模型输入可来自：

- 弱填 ROI。
- 低置信空白 ROI。
- 擦除残留 ROI。
- 涂超出和半涂 ROI。
- 人工复核结果。

在没有数据闭环前，不建议实施 CNN。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 把空白噪声恢复成答案 | 页面证据、中心密度、gap、多阈值投票同时满足 |
| 把涂超出误判成单选 | 用边缘密度、多候选接近、density gap 和尺度扩散做歧义拦截 |
| 把没涂满 ID 强行恢复 | 单选 fallback 不作用于 ID，ID 继续走独立逻辑 |
| 影响正常填涂 | fallback 只处理主流程空白字段 |
| 参数针对样本过拟合 | 参数仅表达通用特征阈值，必须通过四场景回归 |
| 弱填和多选逻辑冲突 | 多选和已有弱多选 fallback 优先，单选 fallback 最后触发 |
| 多尺度放大噪声 | 多尺度特征只加证据，不单独决定答案 |
| 动态阈值过宽 | 多档阈值只投票，最终仍需题内唯一性和 ROI 结构支持 |

## 推荐结论

推荐采用 OMRChecker 专用的“两阶段保守方案”：

1. 主识别流程保持不变。
2. 主流程为空白的单选题才进入 fallback 审查。
3. 用页面级和题内级动态阈值替代固定阈值判断。
4. 用 ROI 多阈值投票增强淡涂稳定性证据。
5. 用小型图像金字塔或多尺度 ROI 增强弱信号观察。
6. 第一阶段只输出 `REVIEW`/`EMPTY` 观测日志。
7. 四场景特征可分后，再启用高置信 `WEAK_MARK` 自动恢复。
8. CNN 只作为远期灰区辅助方向，不进入当前实现主线。

这个方案符合工业级答题卡识别思路，也适合当前 OMRChecker 的代码形态。
它用多层证据、动态阈值、局部 ROI 特征和风险分级来处理淡涂，而不是针对某批样本硬调阈值。
